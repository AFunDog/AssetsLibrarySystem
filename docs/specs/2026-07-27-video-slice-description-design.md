# 视频切片描述方案

## 背景

当前视频描述只支持单个"整体"角度，且将整个视频（包括长视频）直接发送给 LLM。长视频面临 token 上限和细节丢失问题。本方案引入视频切片描述，按场景检测结果将视频切分为多个片段，每个片段独立描述，最后合成整体摘要。

## 架构边界

```
C# 端                              Python 端
 子类型检测                          视频切片流程:
 角度配置 (subtype→angles)           1. PySceneDetect 场景检测
 构建 Prompt + angles        ──→    2. ffmpeg -c copy 提取片段
 决定是否启用切片                     3. 每个片段独立调 LLM
 管理切片阈值参数                     4. 从片段描述合成整体摘要
                                   ──→ 返回 JSON
```

## 关键设计决策

### 1. 两阶段描述流程

**第一阶段：切片描述**
- 视频经 PySceneDetect 检测场景边界
- 每个场景用 ffmpeg `-c copy` 快速提取（无需重编码）
- 每个片段独立发送给 LLM，使用子类型对应的角度组合
- 每个片段得到 `{场景, 动作, 镜头, 整体}` 等角度的完整描述

**第二阶段：合成整体摘要**
- 所有片段的描述文本作为输入，调 LLM（纯文本，无需视频）
- 生成整体摘要，包含场景数量、类型分布、整体风格
- 不重新分析原视频，节省 token

### 2. 切片工具：PySceneDetect

- 使用 `AdaptiveDetector`（自适应阈值，适合多种视频类型）
- 参数：`adaptive_threshold=3.0`, `min_scene_len=15`（帧）
- 返回 `[{start_frame, end_frame, start_sec, end_sec}, ...]`
- 最小场景时长约 0.5 秒，避免过短片段

### 3. 切片阈值

- 视频时长 < 60 秒 → 不分片，直接描述（当前逻辑）
- 视频时长 ≥ 60 秒 → 启用切片流程
- 可配置：`min_scene_len`, `adaptive_threshold`

### 4. 输出 JSON 格式

```json
{
  "整体": {
    "text": "视频包含5个场景：城市街道航拍（0-12s）、人物采访（12-35s）、产品展示（35-55s）...",
    "tags": ["实拍", "城市", "采访", "产品展示"]
  },
  "segments": [
    {
      "start_time": 0.0,
      "end_time": 12.5,
      "场景": { "text": "...", "tags": ["..."] },
      "动作": { "text": "...", "tags": ["..."] },
      "镜头": { "text": "...", "tags": ["..."] },
      "整体": { "text": "...", "tags": ["..."] }
    }
  ]
}
```

## 各子类型的角度配置

| 子类型 | 角度 | 说明 |
|--------|------|------|
| 实拍 | 场景、动作、镜头、整体 | 侧重环境、运动和拍摄手法 |
| 动画/CG | 视觉风格、场景、动作、整体 | 侧重美术风格和动态效果 |
| 游戏录制 | 游戏类型、场景、动作、整体 | 侧重游戏类型和玩法 |
| 默认 | 整体 | 通用简洁描述 |

## 向后兼容

- 短视频（<60s）走原有逻辑，不切片
- 旧数据中 `segments` 字段不存在，搜索时回退到已有逻辑
- 切片后的每个片段角度独立向量化，angle_type 格式为 `seg{N}_{angle}`（如 `seg1_场景`）

## 向量化策略

- 每个片段的每个角度独立向量化
- `angle_type` 格式：`segN_角度名`（如 `seg1_场景`, `seg1_动作`）
- 搜索时，`segN_场景` 和 `segM_场景` 都视为"场景"角度的候选
- `整体` 角度向量化整个视频的综合摘要
